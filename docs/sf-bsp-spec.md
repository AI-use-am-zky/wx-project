# 顺丰 BSP 对接规范（摘录 · 编码必遵）

来源：顺丰开放平台 / BSP 业务文档摘录。后续写顺丰适配器、下单、询价、筛单相关代码时，以本文与官方最新文档为准；字段名、产品编码、错误码勿凭猜测发明。

## 1. 原则

1. 真实字段以官方文档为准；本文件是已确认摘录，未出现在文档中的字段不要写死进页面。
2. 小程序不直连顺丰；`partnerID` / `checkword` / 月结卡只放服务端。
3. 下单时若指定产品，使用本文 **产品编码**（如 `1`=标准快递），并对应表中的货物类型 / 时效类型 / 快件类型。
4. 询价失败走自有价表；业务错误按本文错误码分类处理与提示，勿笼统「系统错误」。
5. 本文产品列表为**通用速运产品**，未列「宠物空运」专码时，不得把特快/标快/快运当成宠物空运履约；宠空以甲方开通产品及补充文档为准。

## 4. 证件类型（18.6 · 中国内地摘要）

个人进出口常用：`001` 身份证、`002` 护照、`003` 军官证、`004` 警察证、`005` 港澳通行证、`006` 台湾通行证。  
公司：`007` 统一社会信用代码、`008` 海关注册编码。  
国际件按目的国另表（新加坡/日本/美国/欧洲/韩国/印度等），编码时按国家选用，勿混用内地编号。

## 5. 签回第三方地址（18.7）

1. **分 2 次下单，先原单后二程单。**  
   - 第一程：`need_return_tracking_no=2`，表示需要签回第三方；成功返回母运单号 + 签回单号。  
   - 第二程：把第一程返回的**签回单号**作为母单号（`mailno`）；原单母单号通过扩展字段传入：`singBackOriNo`（文档示例：`OtherInfo key="singBackOriNo"`）。  
2. 第二程根据 `singBackOriNo` 校验原单存在后，系统生成增值服务 **IN03**。  
3. 第二程下单时 **不要再传** `need_return_tracking_no`。  
4. BSP 将 `need_return_tracking_no` 传给下游时，需转换到 `isSignBack`。

第一期宠途若不做签回第三方，适配器可预留字段但 UI 不暴露。
